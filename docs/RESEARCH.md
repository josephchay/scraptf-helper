# TF2 Flip Desk: research and feasibility report (2026-10-22)

Prepared 2026-10-22 for Flip Desk 0.8.0 (`package.json`). It updates `docs/DESIGN_BRIEF.md` (2026-10-14) and does not replace it: where this report is silent, the brief stands. The hard rules R1-R10 are at the top of `docs/ARCHITECTURE.md`.

How to read the tags:
- **Verified**: read at the primary source on 2026-10-22 (a page, an API spec, a LICENSE file, source code, a keyless JSON response), or read in this repository.
- **Assumption**: a search-index extract of a page that could not be fetched, a forum or community claim, a third-party measurement, or an inference. Each one says which.
- In section 4 only: **[new]** is a fact the brief did not have, **[changed]** updates or contradicts the brief, **[same]** is already in the brief and still holds.

Platform clauses are paraphrased. Read the linked pages for exact wording.

## 1. Scope, method and limits

### 1.1 Lanes searched

Seven research lanes ran on 2026-10-22:

1. **scrap.tf official.** Terms, privacy policy, help and knowledge-base pages on buying from banks, the queue, reservations, limits and cooldowns; any API or developer policy; staff statements; scrap.tf-facing tools seen since the brief.
2. **GitHub, scrap.tf-specific.** Userscripts, extensions, raffle bots, scrapers, unofficial API wrappers, queue or bank automation, notifiers.
3. **GitHub, TF2 trading bots and libraries.** SKU, schema and currency libraries, autopricers, bots, Steam libraries.
4. **Price history and analysis methods.** Datasets, history endpoints, survival and stopping-rule methods, liquidity measures.
5. **backpack.tf official.** OpenAPI spec, Developer Centre, API terms, websocket, limits, classifieds, community prices, users, agent endpoints, site rules, staff announcements.
6. **Other marketplaces and data sources.** marketplace.tf, mannco.store, STN, Steam Community Market, Steam Web API, PriceDB, schema.autobot.tf, prices.tf, key-to-USD sources.
7. **Follow-up (completeness critic).** Filled gaps the other lanes left: cash marketplaces with TF2 APIs (Skinport, DMarket, tf2.tm), exchange rates, Steam's trade-history API, the Trade Protection contradiction, dependency currency, and a way to reassess resources.

### 1.2 Method

- Each lane listed entries (repositories, documents, APIs) with licence, maintenance, compliance verdict and sourced facts, plus platform facts, unsupported capabilities and build ideas.
- Each lane then ran an **adversarial fact-check pass**: every high- and medium-relevance entry and every platform fact was re-read at its source; low-relevance entries got an existence, licence and date check. Corrections were recorded. Examples: `node-tf2-sku` has two runtime dependencies, not none; the bp.tf websocket `deal` field sits on sell-listing updates, not on deletes; Flip Desk already sends `X-App-Context: 440` (an earlier case-sensitive grep missed it); the bptf-autopricer maintainer did not advise splitting tokens or IPs.
- **Static inspection only.** No third-party code was cloned, installed or run. Code was read as raw files from raw.githubusercontent.com.
- **No credentials.** No API key, token, login or form submission was used. A few keyless reads of documented public endpoints were made: bp.tf `IGetUsers/GetImpersonatedUsers` (200), `IGetPriceHistory/v1` and `IGetCurrencies/v1` (403 without a key), the classifieds snapshot (401 without a token); PriceDB `item`, `item-history`, `item-stats` and `cache-stats`; SCM `priceoverview` for the key; Skinport `/v1/items` and `/v1/sales/history`; marketplace.tf `Meta/GetEndpoints/v1` and `Bots/GetBots/v1`; PriceDB Spells `health`; the ECB daily XML.
- **This report adds no new web research.** Its writer re-checked local facts by reading the repository on 2026-10-22: `package.json` (version 0.8.0, `electron` 44.5.0), `NOTICE`, `README.md`, `docs/ARCHITECTURE.md`, `src/shared/venues.ts`, `src/shared/types.ts` (secret names, `OppQuery.sort`), `src/shared/settingsSchema.ts`, `src/service/connectors/` (file list), `src/service/rpcHandlers.ts` (the Steam key test) and `src/service/domain/confidence.ts`, plus a search of `src/` for any Trade Protection setting (none).

## 2. Summary of findings

**scrap.tf is unchanged where it matters, and enforcement looks stricter.** No scrap.tf API, price feed, developer programme or bot policy was found. In 2015 staff refused a queue-status and add-to-queue API because it "would be way to easy to use for botting the site" (assumption-grade index extract of https://forum.scrap.tf/topic/1182-scraptf-api-changes/), and a 2024 thread again found none (https://forum.scrap.tf/topic/27296-scraptf-api/). Staff describe automatic, behaviour-based bot flagging (https://forum.scrap.tf/topic/9011-captcha-or-something-similar, assumption). The most mature raffle bot was archived on 2025-05-08, its author citing "tighter anti-bot measures" (verified, https://github.com/depthbomb/Scraps). So automated monitoring, queueing and buying on scrap.tf stay impossible within scrap.tf's rules and Flip Desk's R1 and R4. Every scrap.tf tool found works by injecting into the site, scraping it, replaying session cookies or automating it; none uses an official interface (section 5.1).

**The queue is a penalty trap, not a strategy.** Help pages (index extracts, assumptions) say joining the queue is what reserves an item, users cannot reserve otherwise, and no reservation length is published (https://scrap.tf/help/kb/114). Letting a bot's offer lapse reportedly blocks buying for about 2 hours, with a site message that warns not to idle in the queue (https://forum.scrap.tf/topic/27463-does-anyone-think-that-the-trading-penalty-for-failing-to-accept-an-item-trade-from-the-bots-is-a-bit-much/). Queue eligibility cannot be tracked, and leaving and rejoining to wait for a lower price reportedly carries a platform penalty on top of breaking R4.

**scrap.tf's pricing is only partly flat, and no markdown schedule is documented.** Logged-out per-item pages exist (`scrap.tf/item/<slug>`): a generic craft hat shows 1.55/1.77 ref, matching the brief, but special hats are priced individually (Team Captain 8.22/10.33 ref), which partly answers brief §8 (index extracts, assumption: https://scrap.tf/item/towering-pillar-of-hats, https://scrap.tf/item/team-captain). The only claim of a time-based markdown concerns a hat-bank "recently traded" section that users reported missing in July 2024 (forum, assumption: https://forum.scrap.tf/topic/27240-where-did-the-recently-traded-section-go). Code from 2018 matched the strings "This item will decrease in price shortly." and "off original price" (verified in https://raw.githubusercontent.com/flyyee/tf2bot-itemscraper-public/master/scraper.cpp); whether scrap.tf still shows them is unknown. Flip Desk's 0.8 buy timing, built from the user's own saves, is the approach this evidence supports.

**backpack.tf has one unused official history endpoint and no sales data.** The official spec documents `GET /IGetPriceHistory/v1` (API key) returning community price changes (`value`, `value_high`, `currency`, `timestamp`); the brief does not mention it and Flip Desk does not call it (verified, https://api.backpack.tf/api/swagger.json). No documented bp.tf endpoint returns sales, completed trades or past order books. The project's own live feed capture (`test/fixtures/bptf/ws-sample.json`, 2026-10-14) contradicts three brief assumptions: `user.online` was true on all 299 live events, so it carries no signal; `deal` sits on sell listings priced below the community price; and 6 of 293 metal values are half-scrap amounts that `Math.round(ref*9)` rounds inconsistently.

**Fees are clearer for mannco, still weak for marketplace.tf, and uncertain for the Steam Market.** mannco's docs state the seller gets 95% rounded up, with a 1-cent minimum fee (verified, https://docs.mannco.store/api-reference/deposit/instant-sell.md), which settles the brief's 95%/92% question. marketplace.tf's 10% still rests on one 2019 forum comment (https://steamcommunity.com/app/440/discussions/0/1747892189247091824/). A secondary article reports a new Steam Market minimum fee and rounding change with no amount given (assumption, https://tech-insider.org/sv/?p=2370). Flip Desk's SCM fee is hint text only (`src/shared/venues.ts`).

**Realised prices exist off backpack.tf.** Skinport's documented keyless API returns realised TF2 sales (24 h to 90 d medians and volumes) at 8 requests per 5 minutes (verified, https://docs.skinport.com/sales/history). On 2026-10-22 the key's realised cash median there was $1.77, against an SCM lowest ask of $2.21 in Steam Wallet funds, so cash and wallet values differ by about 20% (verified reads: https://api.skinport.com/v1/sales/history?app_id=440&currency=USD&market_hash_name=Mann%20Co.%20Supply%20Crate%20Key, https://steamcommunity.com/market/priceoverview/?appid=440&currency=1&market_hash_name=Mann%20Co.%20Supply%20Crate%20Key). mannco and DMarket also expose realised sales, but only with the user's key (https://docs.mannco.store/api-reference/items/get-item-sales-graph.md, https://docs.dmarket.com/v1/swagger.html).

**The largest open risk is Steam Trade Protection.** The brief read Valve's FAQ on 2026-10-14 as covering CS2 only. DMarket's API docs now say Steam's 7-day Trade Protection "applies to every Steam game" (verified as DMarket's wording, https://docs.dmarket.com/v1/swagger.html). Valve's FAQ did not render. If TF2 is covered, every flip is locked and reversible for 7 days. The brief's planned settings flag for this (§5.8, §8) does not exist in `src/` (grep, 2026-10-22).

**An official ledger import is possible, with a known gap.** Steam documents `IEconService/GetTradeHistory` with a user's own Web API key (verified, https://partner.steamgames.com/doc/webapi/IEconService). Each scrap.tf bank purchase and bp.tf sale is a Steam trade, so it records both sides and the time. A key-only call was reported in 2024 to miss trades; the reported fix is an access token, which is the `steamLoginSecure` session cookie (https://dev.doctormckay.com/topic/5842-api) and is forbidden by R9. Flip Desk already has an encrypted slot for a Steam Web API key that nothing uses yet (`src/service/rpcHandlers.ts`).

**Some venues do permit automated buying; Flip Desk does not.** STN documents trade-request endpoints, tf2.tm issues a key for automatic trading, mannco's API has cart, buy-order and instant-sell endpoints, and DMarket has offers and targets (sources in section 6.4). R4 excludes automated buying everywhere, and scrap.tf, the main buy source, never permits it. Changing that is a product decision for the user (section 6.4).

**Security.** The pinned Electron 44.5.0 (2026-09-29) is supported but four minor releases and two Chromium builds behind 44.9.3 (2026-10-21) (verified, https://releases.electronjs.org/releases.json). backpack.tf staff warned of a large rise in successful phishing on 2025-09-30 (https://steamcommunity.com/groups/meetthestats/announcements). Many TF2 tools handle Steam session cookies or commit binaries and secrets (section 7).

**Where Flip Desk 0.8 stands.** Buy timing from the user's saves, watches and alerts, holdings advice and a journal with fees, write-offs and results already cover most requirements within the rules. The main gaps are an exact fee model and break-even price per exit, risk-aware ranking, a Trade Protection setting, ledger import, longer reference histories, and exchange rates. Section 8 ranks the improvements.

## 4. Platform facts

Each item gives its source and carries one tag relative to the 2026-10-14 brief: **[new]**, **[changed]** or **[same]**.

### 4.1 scrap.tf

**Verified**
- scrap.tf HTML (terms, help), forum.scrap.tf and forums.alliedmods.net returned HTTP 403 to a plain fetch on 2026-10-22, as on 2026-10-14. Source: https://scrap.tf/terms (fetch 2026-10-22). **[same]**
- No repository found uses a public scrap.tf item, price or queue API. All read the DOM, call internal `/ajax` endpoints with the user's session cookie and CSRF hash, or drive anti-detection browsers (undetected_chromedriver, SeleniumBase `uc=True`, nodriver). - The session cookie was renamed from `scr_session` to `scraptf` around July 2023 (Scraps commit 992edfd, 2023-07-28). The app must never read either (R9). Source: https://github.com/depthbomb/Scraps/commit/992edfd. **[new]**
- Third-party enforcement evidence: Scraps added honeypot-raffle detection ("modified raffles that ban you upon entering"), ban-reason retrieval and Cloudflare-challenge checks, removed its proxy support, and was archived on 2025-05-08 citing "tighter anti-bot measures". User reports of bans for unlisted raffles are unconfirmed by scrap.tf. Sources: https://github.com/depthbomb/Scraps, https://raw.githubusercontent.com/depthbomb/Scraps/master/CHANGELOG.md, https://github.com/depthbomb/Scraps/issues/69. **[new]**

### 4.8 Skinport, DMarket and tf2.tm

None of these is in the brief; every item is **[new]**.

**Verified**
- Skinport: `/v1/items` and `/v1/sales/history` need no authorization, take `app_id` (default 730) and a currency (16, including USD, EUR, GBP, PLN), allow 8 requests per 5 minutes, are cached 5 minutes and require `Accept-Encoding: br`. `/v1/sales/history` returns realised min, max, average, median and volume for 24 h, 7 d, 30 d and 90 d. Sources: https://docs.skinport.com/items, https://docs.skinport.com/sales/history.
- Skinport serves TF2: `/v1/items?app_id=440` returned about 2.7 MB of items. Key sales on 2026-10-22: 24 h median $1.77 on 1,778 sales; 7 d $1.75 on 7,695; 30 d $1.75 on 33,693; 90 d $1.73 on 107,391. Sources: https://api.skinport.com/v1/items?app_id=440&currency=USD, https://api.skinport.com/v1/sales/history?app_id=440&currency=USD&market_hash_name=Mann%20Co.%20Supply%20Crate%20Key.
- Skinport warns that an API key "GRANTS FULL, UNRESTRICTED ACCESS TO YOUR SKINPORT ACCOUNT". Source: https://docs.skinport.com/introduction/api-key.
- DMarket: every endpoint needs a signed request (`X-Api-Key`, `X-Sign-Date`, `X-Request-Sign` with an Ed25519 signature); TF2 is game id `tf2`; it documents realised last sales (up to 12 months), aggregated best bid and ask, buy orders and offers; rate limiting exists with no numbers; no fee percentages; it states Trade Protection applies to every Steam game. Source: https://docs.dmarket.com/v1/swagger.html.
- tf2.tm: keyless `/history/json/` (last 50 purchases) and an item-database CSV refreshed every minute; keyed trading API; more than 5 requests per second deletes the key; listings update about once a minute; prices in kopecks and rubles; seller fee from `GetDiscounts` (example 6.5%); every transfer needs a Steam mobile confirmation. Source: https://tf2.tm/docs.

**Assumptions**
- Skinport's limit is per IP; its seller fee and its terms on using public endpoints are unknown (https://skinport.com/fees rendered only its title).
- DMarket's TF2 fees and liquidity are unknown, and its Trade Protection sentence may be generic.
- tf2.tm's operator jurisdiction and payment availability are unverified.

### 5.7 Notes on the most important entries

- **bp.tf `IGetPriceHistory/v1`** is the one official, documented interface gained since the brief. It uses the API key the user already stores, on a host and path the net policy already allows (`src/service/net/policy.ts` allows `/api/` paths on backpack.tf). It gives community price changes, so it must be labelled "not sales". Its limit and per-effect coverage need one real call.
- **Steam `IEconService/GetTradeHistory`** is the official route to a ledger with real timestamps and both sides of each trade. Flip Desk already stores an encrypted Steam Web API key that nothing uses (`secrets.test` says "The Steam Web API key is not used yet", `src/service/rpcHandlers.ts`). Completeness with a key alone is unproven.
- **Skinport** is the only keyless source of realised TF2 sale prices found. It is a different venue with a different settlement medium (cash), so it is a reference, not a bp.tf exit.
- **mannco.store** docs now settle its fee and show realised-sales and bid-depth reads with the user's key, but its ToS (unreadable today) bans building a database, and its WebSocket carries every game's market.
- **node-tf2-currencies and juliarose/tf2-price** both treat half a scrap as a unit, which matches what the live feed carries (section 4.2).
- **rep.autobot.tf** shows the ban-combining rule (bp.tf `users/info`, marketplace.tf `GetUserBan/v2`, a community list); Flip Desk's `buyerCheck.ts` covers the first part already, and `isBannedFromBans` does not count the "all features" key, whose meaning is unconfirmed.
- **tf2-automatic** PRs of 2026-10-16 and 2026-10-17 are the freshest bp.tf limit measurements; they are third-party and per token.
- **depthbomb/Scraps** is the best evidence of scrap.tf's enforcement trend: honeypot raffles, Cloudflare checks, and archival over anti-bot measures.

### 5.8 How bots and autopricers price items, compared with Flip Desk

| Tool | What it prices | How (source) |
|---|---|---|
| bliss-autopricer (feeds TF2Autobot bots) | Its own bot's buy and sell quotes | Needs at least 3 bp.tf buy listings; trusted SteamIDs first; with 4-9 listings, the mean of the first 3; with exactly 3 or 10 or more, a z-score ±3 filter and then the mean of the first 3. It skips an update whose buy rises more than 10% above, or whose sell falls more than 10% below, the mean of the last 5 history rows, keeping the old price. A 0.11 ref minimum sell margin. | jack-richards/bptf-autopricer (archived) | Same | Filters on userAgent presence, paint and spell exclusion, block and trust lists, dedupe, outliers (brief §6); uses listings up to about 35 minutes old unless `alwaysQuerySnapshotAPI` is set (README, assumption). Source: https://github.com/jack-richards/bptf-autopricer |
| PriceDB | A reference buy and sell per SKU | Automatic pricer from bp.tf, the SCM and undisclosed others; cannot be set by hand. Source: https://pricedb.io/faq. Its algorithm is undisclosed (assumption that "buy" tracks the mean of top orders). |
| TF2Autobot | Its listings and what it auto-accepts | Takes prices from a pricer (PriceDB in the PriceDB fork) and lists and trades automatically. Sources: https://github.com/TF2Autobot/tf2autobot, https://github.com/TF2-Price-DB/tf2autobot-pricedb |
| Albert12302 dashboard; catlsp/tf2-bptf-bot | Spreads | Highest buy above lowest sell with a 1 ref floor; fair value at the order-book midpoint (READMEs and a commit, assumption). |
| **Flip Desk** | The exit for one unit the user would buy now | One named, live, clean, eligible buy order: eligibility filters (brief §5.2); median of the top five; outliers above 1.30× that median or 1.50× PriceDB sell or the community high; Conservative is the first non-outlier, Instant the best non-outlier bot order (brief §5.5). From 0.7.4 verified orders (seen within 24 h) are preferred; from 0.8 the next buyer, the *One buyer* flag and the price-move reserve; *Pay up to* is the cost ceiling (ARCHITECTURE "0.7.4 round", "0.8 round"). |

What the comparison means:
- **Bots quote both sides and earn a spread over time; a flipper needs one exit now.** A mean of the top three bids can sit above what the second or third buyer would pay for this exact copy. Flip Desk uses the order that would take the item and checks the next one, which is the more conservative choice for a single unit.
- **Bot bids fall at once and rise slowly** (bliss-autopricer's swing limit blocks large buy increases, not decreases). An unknown share of bp.tf bot orders is priced this way (assumption). So the main risk between buying on scrap.tf and trading is a downward move in the bid; a price-move reserve should be sized from downside moves (proposal 12).
- **Neither side knows fills.** Hypothetical executions are "very poor proxies for actual limit-order executions" (https://web.mit.edu/Alo/www/Papers/limit10.html). Flip Desk already words buy orders as demand; order persistence is the honest next step (proposal 6).
- **Fees get dropped easily.** bliss-autopricer's SCM conversion applies no Steam fee. Flip Desk's SCM figure is shown raw and its fee is hint text, so proposal 2 matters.

### 6.4 Note: venues that document automated buying

Some venues do document buying or trading through their APIs:
- **STN**: `POST RequestItemTrade`, `RequestKeyTrade`, `CancelQueueRequest` (https://api.stntrading.eu/swagger.json).
- **tf2.tm**: a key for automatic trading, with a 5-requests-per-second key-deletion rule; every transfer still needs a Steam mobile confirmation (https://tf2.tm/docs).
- **mannco.store**: cart, buy orders, offers, instant sell, deposit, withdraw and payment sessions (https://docs.mannco.store/llms.txt). Its ToS, as read in the brief (§1.6), bans bots and extensions used to automate purchasing, so whether mannco "explicitly permits" automated buying is unclear; the ToS could not be re-read today.
- **DMarket**: offers and targets (buy orders) with signed requests (https://docs.dmarket.com/v1/swagger.html); its ToS was not read.

On STN and tf2.tm the platform condition in the user's requirement is met. Flip Desk's R4 still excludes automated buying everywhere, by product choice. Allowing it on such a venue would be a **deliberate rule change for the user to decide**, not a research finding. The risks to weigh:
- **Real funds spent automatically.** A bug, a stale price, a manipulated listing or a bid that moves between the decision and the fill spends money with no human check. Steam's Scam FAQ already warns about price-manipulated items (brief §1.5).
- **API key custody.** The keys that allow buying also allow more: a Skinport key "GRANTS FULL, UNRESTRICTED ACCESS" (https://docs.skinport.com/introduction/api-key); DMarket's Ed25519 private key signs every request, withdrawals included; STN's key travels in the query string; mannco's JWT is bound to the login IP. R8's safeStorage protects keys at rest, not a compromised process.
- **Steam still needs the user.** Items leave a venue as Steam trades, which need mobile confirmation (https://tf2.tm/docs). Automating that end to end would need `identity_secret`, which R9 forbids.
- **SSA §4.C** forbids non-human-controlled systems interacting with Steam services in any manner (https://store.steampowered.com/subscriber_agreement/english/).
- **It does nothing for scrap.tf**, the main buy source, which never permits it.

## 7. Security considerations

**Secrets.**
- R8 already encrypts the bp.tf key, the bp.tf token and an optional Steam Web API key with safeStorage (`SECRET_NAMES`, `src/shared/types.ts`), redacts them and sends each only to its issuer.
- Any new connector adds a secret with its own blast radius: a marketplace.tf key, a mannco key (exchanged for a 31-day, IP-bound JWT, https://docs.mannco.store/api-reference/authentication.md), an STN key (query string, https://api.stntrading.eu/swagger.json), a DMarket Ed25519 private key (account actions), a Skinport key (full account access). Prefer keyless endpoints (Skinport's market data needs none) and never ask for a key that can trade or withdraw unless the user enables a read-only connector knowingly.
- Prefer headers to query strings where the issuer documents them: Valve documents `x-webapi-key` (https://partner.steamgames.com/doc/webapi_overview/auth). Keys in URLs leak into logs; one dataset script logs errors that may print its key (inference, https://raw.githubusercontent.com/AleXu224/bptf_pricelist/master/scripts/bptfSchema.js), and one old wrapper sends the bp.tf key over plain HTTP (https://raw.githubusercontent.com/KenanY/backpack.tf/master/index.js).
- Steam Web API Terms require telling the user what Steam data is stored and publishing a privacy policy for nonpublic data (https://steamcommunity.com/dev/apiterms). A trade-history import would store counterparty SteamIDs on the user's own journal rows; it needs a stored-data notice.

**Cookie-based libraries.**
- `node-steam-tradeoffer-manager` defaults to an access token (v2.12.0, 2025-05-24), and that token is the `steamLoginSecure` cookie with full account access (https://github.com/DoctorMcKay/node-steam-tradeoffer-manager/releases; https://dev.doctormckay.com/topic/5842-api). `node-steamcommunity`, `node-steam-user` and `node-steam-totp` handle sessions, refresh tokens and authenticator secrets. None may be a Flip Desk dependency (R9).
- Userscripts and extensions reuse cookies quietly: the old profit helper's `GM_xmlhttpRequest` calls omit `anonymous`, so the user's bp.tf cookies go with every scripted fetch (https://www.tampermonkey.net/documentation.php?q=GM_xmlhttpRequest); Warrvin's extension asks for the `cookies` permission its README does not mention and posts Steam accept/decline requests with the page's sessionid (https://raw.githubusercontent.com/Warrvin/tf2-trade-suite-tools/main/wxt.config.ts).
- scrap.tf's session cookie is `scraptf` (formerly `scr_session`); the F21 window must keep never touching cookies (R3, R9).

**Phishing.**
- backpack.tf staff warned on 2025-09-30 of a large recent rise in successful phishing that empties whole inventories (https://steamcommunity.com/groups/meetthestats/announcements). The brief's API-key-scam reminder (§5.8) stands. Flip Desk opens only URLs its link generator builds for allowlisted hosts (brief §7.3.7) and must never open links found in listing notes, buyer names or saved pages.
- bp.tf flags impersonators (keyless `GetImpersonatedUsers`, 168 accounts; `user.flagImpersonated` on the feed). Using them is proposal 11.
- SteamRep tags no longer mean a bp.tf ban (2025-08-19, https://steamcommunity.com/groups/meetthestats/announcements/detail/670592606916314071).

**Supply chain.**
- Several repositories commit binaries or secrets: `scraper.exe` (flyyee), `chromedriver.exe` (AmityBlamity), `cookies.pkl` (Metal079), `scraptf-cookies.json` (DixieF), a `.env` (TF2TradeLogger). Never run or copy from them.
- GitHub searches for "bptf" return SEO link-farm repositories created in September-October 2026 (https://github.com/wxg3vv7i76/bptfq). Two websocket mirrors default to `wss://ws-backpack.tf/ws`, which is not a backpack.tf host and whose owner is unknown (https://raw.githubusercontent.com/purplebarber/backpack.tf-ws-service/main/src/bptf_websocket.py).
- Any dev-only dependency added for differential tests (tf2-item-format, tf2-item-parser) should be pinned at a version at least two weeks old and must never reach the runtime bundle; tf2-item-parser's `Item.init()` fetches from Steam when given a key (https://github.com/peleicht/tf2-item-parser).
- The hyunjun fee library has a negative-fee bug at 0-1 cent (static reading, https://raw.githubusercontent.com/hyunjun12312/steam-market-fee-calculator/main/src/fees.js); write fee code independently.
- Only Electron's currency was checked in this pass. The runtime dependencies (`parse5` 8.0.1, `socket.io-client` 4.8.4, `ws` 8.22.0, `zod` 4.6.5, from `package.json`) were not; `npm audit` and the brief's two-week pinning rule (§7.3.15) still apply.

**Electron version currency.**
- `package.json` pins `electron` 44.5.0 (released 2026-09-29, Chromium 152.0.7977.130). 44.x is supported until 2027-03-02 (tentative); 42 reached end of life on 2026-10-20 and 45 went stable the same day. Newer 44.x patches carry newer Chromium builds: 44.7.1 and 44.7.2 (2026-10-13, .149), 44.8.0 (2026-10-15, .167), up to 44.9.3 (2026-10-21). Sources: https://releases.electronjs.org/schedule, https://releases.electronjs.org/releases.json.
- Under the two-week rule, 44.7.2 is eligible from 2026-10-27 and 44.8.0 from 2026-10-29. The brief named 44.7.2 as the target (§7.1); the pin was never moved. That Chromium patch bumps carry security fixes is an inference; the release notes were not read.

**Untrusted saved pages and third-party data.**
- Saved pages stay untrusted input: parse5 with no script execution, a 20 MB limit (also after decoding), at most 2,000 MHTML parts, nothing inside a file fetched, opened or followed (ARCHITECTURE R10, F18; README known limits). A saved Wayback capture imports as the live page.
- The F21 window reads with one pinned script and never reads challenge, error or sign-in pages when they load (R3). Proposal 14 adds a phrase check ("Please complete the following captcha to enter Scrap.TF") as extra evidence of a challenge served with an unexpected status.
- A bp.tf 429 can be an HTML page with a Cloudflare challenge script (https://github.com/jack-richards/bptf-autopricer/issues/17); it must take R7's challenge path, never the retry path.
- Local relays with no authentication (TF2-Price-DB/backpack-tf-socket-relay, dixon2004's websocket) are what brief §7.3.10 warns against; Flip Desk runs no local server.
